# 🧠 核心记忆 — 动态加载 skill

## 加载流程

每次回答用户前，执行以下流程：

### 步骤 1：读取核心记忆（必读）

用 `Read` 工具读取：
```
Tools/Claudian Memory/🧠 核心记忆.md
```

这是**必须执行的步骤** — 它包含身份、铁律和事务类型映射表。

### 步骤 2：根据任务类型，按需加载模块

根据用户请求的内容，判断所属事务类型，并**追加读取**对应的模块文件：

| 事务类型 | 用户请求特征 | 额外加载文件 |
|---------|------------|------------|
| **笔记写作** | 含"写/改/创建笔记"、"整理"/"知识"、"note"、"markdown"等 | `Tools/Claudian Memory/📝 笔记规范.md` |
| **识图/OCR** | 含"识图"、"识别"、"转录"、"OCR"、"vision"、"图片转文字"等 | `Tools/Claudian Memory/🖼️ 识图规则.md` |
| **图床/图片上传** | 含"上传"、"OSS"、"图床"、"外链"、"图片"、"img"等 | `Tools/Claudian Memory/🤖 工具配置.md` |
| **工具配置/查询** | 含"配置"、"工具"、"脚本"、"环境"等 | `Tools/Claudian Memory/🤖 工具配置.md` |
| **Vault 文件管理** | 含"结构"、"目录"、"文件夹"、"导航"、"位置"等 | `Tools/Claudian Memory/📂 Vault 结构.md` |
| **多类型混合** | 如"识图后写入笔记" | 加载对应的所有模块文件 |
| **通用问答/知识查询** | 不匹配以上任何类型 | 无需额外加载 |

### 步骤 3：若有变更提示，重新读取

如果用户在对话中提到了新的配置变更或规则更新，重新读取 `🧠 核心记忆.md` 和相关模块文件。

## 设计原则

- **最小加载**：只读当前任务需要的配置，避免浪费上下文
- **按需组合**：多类型任务叠加加载对应模块
- **核心优先**：`🧠 核心记忆.md` 始终先读，提供全局上下文
- **模块自治**：每个模块文件可独立理解，包含自我描述标签
