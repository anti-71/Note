解决临界区问题最简单的工具是 **互斥锁**

##### 核心操作规则

- 一个进程在进入临界区前调用 acquire() 以获得锁
- 在退出临界区时调用 release() 以释放锁

##### 锁状态标识

每个互斥锁包含一个布尔变量 available，用于表示锁是否可用：

- 若锁可用，则调用 acquire() 会成功，并将锁置为不可用
- 当一个进程试图获取不可用的锁时，它将被阻塞，直到锁被释放

##### 过程描述

```c
acquire() {                //获得锁的定义
    while(!available)
        ;                  //忙等待
    available=false;       //获得锁
}
release() {                //释放锁的定义
    available=true;        //释放锁
}
```

acquire() 或 release() 的执行必须是 **原子操作**，因此互斥锁通常采用 **硬件机制** 来实现

上述互斥锁也称 **自旋锁**

##### 主要缺点

**忙等待**

当有一个进程在临界区中时，任何其他进程在进入临界区前都必须连续循环调用 acquire()

类似的还有前面介绍的单标志法、TS 指令和 Swap 指令

当多个进程共享同一 CPU 时，这种连续循环显然浪费了 CPU 周期

##### 自旋锁的适用场景

通常用于多处理器系统，一个线程可以在一个处理器上 “旋转”，而不影响其他线程的执行

##### 自旋锁的优点

进程在等待锁期间没有上下文切换；若持有锁的时间较短，则等待代价较低
