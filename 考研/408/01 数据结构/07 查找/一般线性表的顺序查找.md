##### 顺序查找的基本思想

1. 从线性表的一端开始，逐个检查元素的关键字是否满足给定条件
2. 若查找到某个元素的关键字满足条件，则查找成功，返回该元素在线性表中的位置
3. 若已查至表的另一端仍未找到符合条件的元素，则返回查找失败的信息

##### 算法实现

```c
typedef struct{          //查找表的数据结构（顺序表）
    ElemType *elem;      //动态数组基址
    int TableLen;        //表的长度
}SSTable;
int Search_Seq(SSTable ST,ElemType key){
    ST.elem[0]=key;                        //“哨兵”
    for(int i=ST.TableLen;ST.elem[i]!=key;--i); //从后往前找
    return i;  //若查找成功，则返回元素下标；若查找失败，则返回0
}
```

##### 哨兵的作用

上述算法中，将 ST.elem[0] 称为 **哨兵**

引入哨兵的目的是 **避免在循环中反复判断数组下标是否越界**

算法从表尾（下标 TableLen）向前查找，一旦 ST.elem[i]\==key，即返回 i，表示查找成功

否则，循环最终会在 i=0 时终止（因为 ST.elem[0]\==key），此时返回 0，表示查找失败

通过设置哨兵，可以省去边界判断，从而提高程序效率

##### 平均查找长度分析

对于含 n 个元素的表，若给定关键字 key 与表中第 i 个元素相等，即定位第 i 个元素时，需进行 n - i + 1 次关键字比较，即 $C_i=n-i+1$ 查找成功的平均查找长度为 

$$\text{ASL}_{成功}=\sum_{i=1}^{n} P_i(n-i+1)$$

当每个元素的查找概率相等（$P_i=1/n$）时，有 

$$\text{ASL}_{成功}=\sum_{i=1}^{n} P_i(n-i+1)=\frac{n+1}{2}$$

查找不成功时，与表中各关键字的比较次数显然是 n + 1 次，即 $\text{ASL}_{不成功}=n+1$ 

通常，查找表中记录的查找概率并不相等

若能预先获知各记录的查找概率，则应将记录按查找概率由大到小重新排列，使 **高频元素靠近查找起点**，从而降低平均查找长度

##### 顺序查找的主要缺点

当 n 较大时，平均查找长度较大，效率较低

##### 优点

对存储结构无要求 —— 无论是顺序存储还是链式存储均可使用，且不要求表中记录按关键字有序

此外还需注意，**链表只能采用顺序查找**
