##### 1）结点结构

> [!note]
> $p_0$ 所指子树所有结点的关键字均小于 $k_1$，$p_1$ 所指子树所有结点的关键字均大于 $k_1$

| 字段 | 说明 |
|------|------|
| n | n 为结点内关键字的个数（一般省略） |
| $k_i$ | $k_i$ 为关键字 |
| $p_i$ | $p_i$ 为指向子树根结点的指针 |

##### 2）性质

| | B 树 | B+ 树 |
|----|------|-------|
| 关键字和子树的关系 | n 个关键字对应 n+1 棵子树 | n 个关键字对应 n 棵子树 |
| 根结点子树 | $[2, m]$ | $[2, m]$ |
| 根结点关键字 | $[1, m-1]$ | $[2, m]$ |
| 非根结点子树 | $[\lceil m/2 \rceil, m]$ | $[\lceil m/2 \rceil, m]$ |
| 非根结点关键字 | $[\lceil m/2 \rceil - 1, m-1]$ | $[\lceil m/2 \rceil, m]$ |
| 叶子结点 / 失败结点 / 终端结点 | 所有叶子结点都在同一层且不带信息（可类比折半查找判定树的失败结点） | 叶子结点中包含了所有关键字信息以及指向含这些关键字记录的指针，叶子结点本身按照关键字大小从小到大顺序链接 |
| 查找方式 | 随机查找 | 随机查找和顺序查找 |
| 高度 | $\log_m (n+1) \leqslant h \leqslant \log_{\lceil \frac{m}{2} \rceil} (\frac{n+1}{2}) + 1$ | |

##### 3）查找

- **B 树：** 从根结点出发，在结点内按关键字有序折半查找，命中则成功；否则按指针进入下一层子树，直到命中或到达失败结点（叶子）表示查找失败
- **B+ 树：** 既可像 B 树一样从根结点随机查找，也可从最左下角的叶子结点开始沿链表顺序查找；由于所有关键字都存放在叶子结点中，查找必须进行到叶子结点才能确定结果

##### 4）插入

- **B 树**

| 情况 | 操作 |
|------|------|
| 1. 插入后结点关键字个数 $\leqslant m-1$ | 直接插入 |
| 2. 插入后结点关键字个数 $> m-1$ | 结点（插入后的）第 $\lceil m/2 \rceil$ 个关键字进入父结点，原结点一分为二 |

- **B+ 树**

| 情况 | 操作 |
|------|------|
| 1. 插入后结点关键字个数 $\leqslant m$ | 直接插入 |
| 2. 插入后结点关键字个数 $> m$ | 从第 $\lceil m/2 \rceil$ 个关键字开始，原结点一分为二 |

> [!note]
> 插入过程中要时刻注意是否需要修改索引中的关键字

##### 5）删除

> [!tip]
> 为了方便叙述，研究删除所讨论的终端结点指的都是最下排的一层含关键字的结点，而不是不含任何信息的叶子结点 / 外部结点

- **B 树**

| 情况 | 操作 |
|------|------|
| 1. 被删关键字不在终端结点 | 用被删关键字的前驱 / 后继关键字代替被删关键字的位置，转化为删除终端结点关键字的情况 |
| 2. 被删关键字在终端结点 | 2-1 删除后关键字个数 $\geqslant \lceil m/2 \rceil - 1$，直接删除<br>2-2 删除后关键字 $< \lceil m/2 \rceil - 1$ 且兄弟够借，父下子上<br>2-3 删除后关键字 $< \lceil m/2 \rceil - 1$ 且兄弟不够借，父下与子合并 |

- **B+ 树**

| 情况 | 操作 |
|------|------|
| 1. 被删关键字在终端结点 | 1-1 删除后关键字个数 $\geqslant \lceil m/2 \rceil$，直接删除<br>1-2 删除后关键字 $< \lceil m/2 \rceil$ 且兄弟够借，兄弟结点的关键字进入当前结点<br>1-3 删除后关键字 $< \lceil m/2 \rceil$ 且兄弟不够借，当前结点与兄弟结点合并 |

> [!note]
> 删除过程中要时刻保持终端结点关键字和非终端结点关键字的一致性
