**递归下降分析（Recursive-descent Parsing）** 是一种自顶向下的语法分析方法，将非终结符的文法规则视为识别该非终结符的过程定义，规则右侧指定该过程代码的结构

##### 基本思想

将 **非终结符** $A$ 的文法规则视为识别 $A$ 的过程定义，规则右侧的内容决定该过程的代码结构

##### 核心操作：match

`match(expectedToken)` 过程的核心逻辑：

- 如果当前 `token` 等于 `expectedToken`，则获取下一个 `token`
- 否则报错

```pascal
procedure match(expectedToken);
begin
    if current_token = expectedToken then
        get_next_token
    else
        error("Syntax error");
end;
```

##### 表达式文法的递归下降结构

表达式文法：
```ebnf
expr   → expr addop term | term
addop  → + | -
term   → term mulop factor | factor
mulop  → * | /
factor → (expr) | number
```

**匹配过程**：从起始符号 `expr` 开始，递归调用对应的解析过程，最终匹配完整的输入串

##### 产生式选择的歧义性

当两个产生式以相同的非终结符开头时，解析器无法通过单一前瞻确定选择哪条路径：

```ebnf
A → B C
A → B D
```

**解决方案**：

- **计算 First 集合**：若 $\text{First}(BC)$ 和 $\text{First}(BD)$ 的交集为空，则可通过当前 token 选择正确的产生式
- **冲突处理**：若存在交集，需重构文法（如提取左公因子）

##### ε 产生式的 Follow 集合依赖

对于形如 $A \to \varepsilon$ 的产生式，解析器需判断是否选择该产生式，需依赖 $\text{Follow}(A)$ 集合：

```ebnf
stmt → if (exp) stmt [else stmt]
     | while (exp) stmt
     | ε
```

当解析 `stmt` 时，若当前 token 不在 $\text{First}(stmt)$ 中，但属于 $\text{Follow}(stmt)$（如 `}` 或文件结束符），则选择 $\varepsilon$
