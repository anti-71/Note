##### 属性计算算法

---

##### 属性计算的总体分类

属性计算算法按**遍历次数**和**方向**可分为以下几类：

| 算法 | 遍历次数 | 属性支持 | 特点 |
|:---:|:---:|:---:|:---|
| **后序遍历（Post-Order）** | 1 次 | 仅综合属性 | 自底向上，S-属性文法的天然计算方案 |
| **前序遍历（Pre-Order）** | 1 次 | 仅继承属性 | 自顶向下，较少单独使用 |
| **两趟计算（Two-Pass）** | 2 次 | 综合 + 继承 | 先继承（前序）后综合（后序），L-属性文法 |
| **多趟计算（Multi-Pass）** | $\geqslantslant 2$ 次 | 任意属性 | 通过迭代逐步确定属性值 |

---

##### 后序遍历算法（S-属性计算）

适用于 **S-属性文法**（仅综合属性）：

```
procedure postOrderEval(node N):
    for each child C of N (从左到右):
        postOrderEval(C)
    // 此时所有子节点的综合属性已计算完毕
    for each 产生式 p = N.production:
        for each 综合属性 s of N:
            根据 p 的语义规则计算 N.s
```

> [!abstract] 后序遍历的本质：**先处理子节点，再处理父节点**，确保计算某节点属性时其依赖的子节点属性均已就绪

---

##### 前序遍历算法（继承属性计算）

适用于仅含继承属性的（子）文法：

```
procedure preOrderEval(node N):
    // 先计算当前节点的继承属性（来自父节点或兄弟节点）
    for each 继承属性 i of N:
        根据父节点传来的信息计算 N.i
    // 将继承属性传递给子节点
    for each child C of N:
        preOrderEval(C)
```

> [!note] 前序遍历在语义分析中**很少单独使用**，通常作为两趟算法的第一趟

---

##### 两趟计算算法

**两趟计算**综合了前序和后序遍历：先通过前序遍历传递**继承属性**，再通过后序遍历计算**综合属性**

适用于 **L-属性文法**：

```
procedure twoPassEval(node N):
    // 第一趟：前序 — 计算 N 的继承属性并传递给子节点
    for each 继承属性 i of N:
        N.i = 根据父节点/左兄弟计算
    for each child C of N (从左到右):
        C.inh = 根据 N 的属性和已处理兄弟的属性计算
        twoPassEval(C)   // 递归处理 C

    // 第二趟：后序 — 计算 N 的综合属性
    for each 综合属性 s of N:
        N.s = 根据子节点属性计算
```

---

##### 两趟计算示例

```
     D (env = global)
    / \
   T   D₁
  /   / \
int  id  D₂
```

**第一趟（前序传递继承属性）：**

| 节点 | 传入的继承属性 | 说明 |
|:---:|:---|:---|
| $D$ | $env = global$ | 顶层环境 |
| $T$ | $inh = global\_type$ | 继承类型信息 |
| $D_1$ | $env = global \cup \{i : int\}$ | 添加声明后更新环境 |
| $D_2$ | $env = global \cup \{i : int\} \cup \{j : int\}$ | 继续扩展环境 |

**第二趟（后序传递综合属性）：**

| 节点 | 传出的综合属性 | 说明 |
|:---:|:---|:---|
| $D_2$ | $syn = env_2$ | 返回完整环境 |
| $D_1$ | $syn = env_1$ | 返回合并环境 |
| $D$  | $syn = env_1$ | 最终环境 |

##### 多趟计算算法

对于**一般属性文法**（非 L-属性），可能需要多趟计算：

- 第 1 趟：计算不依赖其他属性的**基础综合属性**
- 第 2 趟：利用第 1 趟结果计算部分**继承属性**
- 第 $k$ 趟：继续利用之前计算的属性计算剩余属性
- 直至 **不再有新的属性值变化**（不动点）

> [!warning] 多趟计算在工程中**效率较低**——实际编译器倾向于使用 **L-属性文法** 和 **两趟计算**

---

##### 属性计算的实现策略对比

| 策略 | 实现难度 | 效率 | 适用范围 |
|:---:|:---:|:---:|:---:|
| **解析时即时计算** | 低 | 高 | S-属性文法 / L-属性文法（SDT） |
| **建立依赖图 + 拓扑排序** | 高 | 中 | 一般属性文法 |
| **两趟分别遍历** | 中 | 高 | L-属性文法 |
| **多趟迭代** | 中 | 低 | 复杂非 L-属性文法 |
