##### 依赖图的定义

**依赖图（Dependency Graph）** 是表示属性之间计算依赖关系的有向图对于给定的语法树和关联的属性文法，依赖图描述了每个属性实例（attribute instance）之间的先后计算次序

##### 依赖图的构建规则

对于每个产生式 $p: X_0 \to X_1 X_2 \dots X_n$ 及其语义规则，为每条规则引入依赖边：

| 语义规则类型 | 边的方向 |
|:---|:---|
| $X_i.a = f(\dots, X_j.b, \dots)$ | $X_j.b \to X_i.a$ |
| 函数调用产生的隐式依赖 | 取决于函数的参数属性 |

##### 依赖图示例

文法：

$$
\begin{aligned}
E &\to E_1 + T \quad &&\implies \quad E.val = E_1.val + T.val \\
E &\to T \quad &&\implies \quad E.val = T.val \\
T &\to \text{num} \quad &&\implies \quad T.val = \text{num}.lexval
\end{aligned}
$$

对应表达式 `3 + 5` 的依赖图：

```
    E.val
      ↑
     / \
    /   \
E₁.val   T.val
   ↑       ↑
   |       |
T.val   num.lexval
   ↑
   |
num.lexval
```

> [!note] 依赖图中不存在环，则属性可按**拓扑排序**计算

---

##### 拓扑排序与计算顺序

**拓扑排序（Topological Sort）** 是有向无环图（DAG）的一种线性排序，满足：对于每条边 $u \to v$，$u$ 在排序中出现在 $v$ 之前

- 若依赖图为 **DAG**，则拓扑排序给出了**合法的属性计算顺序**
- 若依赖图**存在环**，则该属性文法**不可递归计算**——通常视为文法设计错误

##### 不同属性文法的依赖图特性

| 属性文法类型 | 依赖图形式 | 计算顺序 |
|:---|:---|:---|
| **S-属性文法** | 边仅自底向上 | 后序遍历即拓扑排序 |
| **L-属性文法** | 边自左向右、自顶向下（无交叉依赖） | DFS 左到右遍历 |
| **一般属性文法** | 可能任意复杂 | 需显式拓扑排序 |

---

##### 依赖图的分析算法

**步骤：**

1. 为语法树中的每个属性实例创建节点
2. 对于每个产生式实例的每条语义规则，添加对应的依赖边
3. 检查依赖图是否有环
   - 若存在环 → 属性文法非法，需要重新设计
   - 若无环 → 选择一种拓扑排序作为计算顺序

```
依赖图构建算法:
─────────────────────────
for each 语法树节点 N:
    for each 产生式 p = N.production:
        for each 语义规则 r in p.rules:
            for each 依赖关系 (a → b) in r:
                if a 与 b 在语法树中有对应实例:
                    添加有向边 a → b
检查: if 存在环 → 错误
排序: 拓扑排序 → 计算计划
```

> [!tip] 大型语法树的依赖图可能包含数千个节点，显式构建完整的依赖图在工程上**开销较大**因此实际编译器通常利用 **S-属性文法** 或 **L-属性文法** 的约束，避免显式的依赖图构建，直接在解析过程中按固定顺序计算属性
